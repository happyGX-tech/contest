# 红方基线

本目录保存红方可运行策略及其共享信息契约。R0--R5 是稳定对照基线；R6--R8 扩展前导、编组和天眼时序；R9 将 R8 的任务层与学习机动层组合为正式分层策略。

## 共同信息边界

所有 R0--R9 在开局使用 core 的 `TrainingEnv._get_init_ship_observation()`。尽管函数名中有 `ship`，它返回的是完整的初始可用目标目录：

- `9400`：母巢；
- `9500`：暗巢；
- `9600`：哨卫巢。

每条目录项包含 ID、真实初始经纬高、血量、类型、阵营、初始探测和通信字段。策略通过 `priors.initial_targets_from_observation()` 将其转换为 `TargetPrior`；不再做类型过滤。策略还可读取每个红方平台自身报告的位置、类型、存活状态与已发射状态，但不读取 `TrainingEnv._get_observation()` 的全局态势。

当前场景中 `9500` 没有运动逻辑，初始坐标即整局真实坐标。R0--R4 的目标目录在单局中保持静态；R5 只融合己方收到的 `detectInfo` 中的同 ID、同类型目标位置，并将冷却期（默认 5 步）内的多个事件合并为一次重规划。

## R0--R9

| 基线 | 名称 | 分配方式 | 适用作用 |
|---|---|---|---|
| R0 | `r0_random` | 对完整初始目录做可复现随机分配 | 零知识偏好的随机对照 |
| R1 | `r1_priority` | 按目标价值、距离、已覆盖数量和平台—目标基础命中能力逐个平台贪心选择 | 能力匹配的规则对照 |
| R2 | `r2_static_assignment` | 开局一次性生成固定分配；小规模精确求解，大规模确定性贪心 | 静态全局分配对照 |
| R3 | `r3_wave_schedule` | 开局固定三波，每类平台均匀进入各波，波间隔 40 步 | 固定多波次编成对照；不做后续重规划 |
| R4 | `r4_rolling_rules` | 每 20 步重新分配尚未发射的平台，每次最多释放其 25% | 仅按平台状态、固定周期滚动的波次对照 |
| R5 | `r5_event_rolling` | 航迹位置更新或平台失联时重分配未发射平台 | 合法信息事件驱动的滚动对照 |
| R6 | `r6_frontload_decoy` | 以自爆虫群密度、己方损失和剩余兵力滚动控制 L 探针/主攻批次 | 前导压力/牵制对照；没有独立侦察含义 |
| R7 | `r7_strike_packages` | 继承 R6 指标，在主攻批次生成 H/M 同目标包 | 异构平台的滚动发射编组对照 |
| R8 | `r8_satellite_packages` | R7 + 每轮新高价值打击包一枚 H 的天眼请求 | core 天眼命中增强的滚动协同对照 |
| R9 | `r9_hierarchical_learning` | R8 任务层 + 共享 PPO/MAPPO 机动 Actor | 正式分层学习入口 |

R0--R5 的共同发射时序为 H/M/L 分别延后 0/10/20 步。R6--R9 每 5 步重规划：初始探针批次为剩余兵力的 15%，低压力主攻为 30%，高压力收缩到 12%；R7--R9 包内 M 先发、H 延后 3 步。R1--R9 的能力项来自 core 当前的基础命中率：H/M 优先 `9400/9600`，L 优先 `9500`。R0 不施加该偏好，保留纯随机特性。

R3 和 R4 不是上下替代关系：R3 在开局明确固定每波组成和时间，而 R4 隔固定周期根据未发射平台重算。两者共同构成后续闭环策略的两个受控参照。

R5 不会读取 `TrainingEnv._get_observation()`。环境只批量汇聚各存活红方平台已经收到的隔离观测，再由指挥器融合其中的航迹；`DetectInfo` 当前不含目标血量，因此 R5 不做残血补火或毁伤确认的推断。R6--R8 同样只读取该目录和己方观测。

## R9 分层学习

R9 的上层是 R8 的合法任务层：只以初始目录、已收到的 `detectInfo`、己方损失和自爆虫群压力生成任务、编组与天眼请求。下层共享 PPO/MAPPO Actor 只能读取本机隔离观测及五维上层上下文：目标类别 one-hot、压力值、已发射比例。R9 必须选择 `random_masked`、`ppo` 或 `mappo` 机动层；其中前者仅验证接线，后两者需要 R9 专用 90 维 checkpoint。MAPPO Critic 的全局态势仅在显式训练时可用。

新增策略应实现 `build_red_baseline()` 对应的决策接口，并补充 `tests/test_red_baselines.py`；禁止直接读取全局环境实体表。

## 学习机动层

`learning/` 的 PPO/MAPPO 可与 R0--R8 组合使用，也构成 R9 的下层 Actor。部署阶段仅编码隔离观测；显式训练阶段，`TrainingEnv` 才将完整态势交给 MAPPO 的集中式 Critic。`random_masked` 仅用于在没有 PyTorch 时验证观测和动作链路，不是性能基线。
